## 1. Project Overview

### What This Is

A **React Single Page Application (SPA)** that serves as the frontend for a Property & Vehicle Valuation Report Generation Platform. The platform is built for **Sri Lankan professional valuers** — people who assess land, buildings, and vehicles for banks, courts, insurance, and private clients.

The frontend allows valuers to:
- Register/login with email or Google OAuth
- Fill out multi-step valuation report forms (property, multi-property, vehicle)
- Place properties on Google Maps with geocoding
- Upload and manage photos of buildings and vehicles
- Auto-save drafts to the backend
- Generate professional DOCX reports
- Manage their professional profile and letterhead templates
- Browse a vehicle template library

### How It Connects to the Backend

- **Development**: Vite dev server proxies `/api/*` requests to `http://localhost:8000` (FastAPI backend)
- **Production**: The `VITE_API_URL` environment variable points to the deployed backend (e.g., `https://api.valuerpro.online`)
- **Authentication**: JWT bearer tokens stored in AES-encrypted sessionStorage
- **CSRF Protection**: The frontend reads a `csrf_token` cookie and attaches it as `X-CSRF-Token` header on all state-changing requests (POST, PUT, DELETE, PATCH)
- **Cookies**: `withCredentials: true` on Axios ensures cookies are sent cross-origin

## 3. Entry Point & App Bootstrap

### `main.tsx` — Application Entry Point

**File**: `src/main.tsx` (47 lines)

This is where the React application starts. The boot sequence is:

1. **Sentry Initialization** (production only): If `VITE_SENTRY_DSN` is set and mode is `production`, Sentry is initialized with:
   - Browser tracing integration (10% of transactions sampled)
   - Session replay (10% of sessions, 100% of error sessions)
   - Text masking and media blocking in replays
   - `beforeSend` hook that strips `Authorization` headers from error reports

2. **React DOM Render**: Creates root on `#root` div and renders:
   ```
   React.StrictMode
     └── ErrorBoundary (catches unhandled React errors)
           └── App (root component)
   ```

### `App.tsx` — Root Component & Routing

**File**: `src/App.tsx` (298 lines)

The `App` component sets up the entire application structure:

1. **Legacy Draft Cleanup**: On mount, calls `clearLegacyDrafts()` to remove old localStorage data from the v0.0 form system (one-time migration).

2. **Provider Hierarchy**:
   ```
   BrowserRouter
     └── AuthProvider (provides user state, login/logout methods)
           └── AppRoutes (renders the correct route)
   ```

3. **Inline Components**:
   - `LandingPage` (lines 22–125): The public landing page with animated gradient backgrounds, feature cards (Security, Multi-User, Speed), and CTA buttons linking to `/register` and `/login`.
   - `LegacyFormPage` (lines 128–144): Renders the original `DataCollectionForm` component for backward compatibility/testing.

4. **AppRoutes** (lines 146–281): The main routing component that checks `isLoading` from auth context and shows a spinner while auth state is being determined.

## 5. Authentication

### `AuthContext.tsx` — Authentication State Management

**File**: `src/contexts/AuthContext.tsx` (179 lines)

Provides global authentication state via React Context. The `AuthProvider` wraps the entire app inside the `Router`.

#### Context Interface

```typescript
interface AuthContextType {
  user: User | null;             // Current user object (null if logged out)
  isLoading: boolean;            // True while checking initial auth state
  login: (email, password) => Promise<void>;
  loginWithGoogle: (code, state) => Promise<void>;
  register: (email, password, fullName, phone?) => Promise<void>;
  logout: () => Promise<void>;
  updateUser: (userData: Partial<User>) => void;      // Local state update only
  updateUserProfile: (userData) => Promise<void>;      // API call + state update
  sendVerificationEmail: () => Promise<void>;
}
```

#### Boot Sequence (on mount)

1. **CSRF Initialization**: Calls `initializeCSRF()` in the background (non-blocking). This makes a GET to `/api/csrf-token` to set the CSRF cookie before any state-changing requests.
2. **Token Check**: Reads the auth token from encrypted sessionStorage via `authTokenStorage.getToken()`.
3. **User Fetch**: If token exists, sets the Axios Authorization header and calls `GET /api/auth/me` to fetch the current user.
4. **Error Handling**: If the token is invalid/expired, clears all stored auth data.
5. **Loading Complete**: Sets `isLoading = false` so the UI can render.

#### Authentication Flow

- **Login**: Calls `POST /api/auth/login` → receives `{ access_token, user }` → stores token and user data in encrypted sessionStorage → sets Axios header → refreshes CSRF.
- **Register**: Calls `POST /api/auth/register` → same flow as login. Handles "Email already registered" error specifically.
- **Google OAuth**: Calls `POST /api/auth/google/callback` with authorization code and state → same token storage flow.
- **Logout**: Calls `POST /api/auth/logout` to revoke the token server-side → clears sessionStorage and Axios header regardless of API success.
- **Profile Update**: Calls `PUT /api/profile` → updates local user state with response data.

#### Token Storage

Tokens are stored using the `authTokenStorage` helper from `secureStorage.ts`:
- **Storage**: `sessionStorage` (cleared when browser tab closes)
- **Encryption**: AES-256 via CryptoJS with a key derived from browser fingerprint (user agent, language, screen dimensions, timezone offset)
- **Keys**: `authToken` for the JWT, `user` for the user data object

## 6. API Service Layer

### `api.ts` — Centralized HTTP Client

**File**: `src/services/api.ts` (713 lines)

The entire API communication layer is in this single file. It creates an Axios instance with interceptors and exports organized API namespaces.

#### Axios Instance Configuration

```typescript
const api = axios.create({
  baseURL: API_BASE_URL,      // From config (VITE_API_URL or localhost:8000)
  timeout: 300000,            // 5 minutes (extended for large file uploads)
  withCredentials: true,      // Send cookies (required for CSRF)
  headers: { 'Content-Type': 'application/json' },
});
```

#### CSRF Request Interceptor

Runs before every request. For unsafe methods (POST, PUT, DELETE, PATCH):
1. Reads the `csrf_token` cookie from `document.cookie`
2. Attaches it as `X-CSRF-Token` header

#### Response Interceptor (Error Handling + Retry)

The response interceptor handles:

| Status | Behavior |
|--------|----------|
| 401 | Auth endpoints: throw error for component to handle. Other endpoints: redirect to `/login` after clearing auth |
| 403 | If CSRF error, retry once after 100ms. Otherwise throw "Access forbidden" |
| 404 | Throw "Resource not found" |
| 413 | Throw "File too large (max 10MB)" |
| 422 | Parse field-specific validation errors from backend |
| 429 | Retry with exponential backoff (up to 3 attempts) |
| 500/502/503/504 | Retry with exponential backoff (up to 3 attempts) |
| Network errors | Retry on timeout, throw user-friendly message |

**Retry Logic**: Maximum 3 retries, exponential backoff (1s base × 2^attempt). Retryable status codes: 408, 429, 500, 502, 503, 504.

## 10. Custom Hooks

### `useDraftManager` — Auto-Save Draft State

**File**: `src/hooks/useDraftManager.ts` (177 lines)

Manages saving form drafts to the backend with deduplication and debouncing.

**Config**: `reportId?`, `isEditMode`, `formMethods` (watch, getValues, setValue), `debounceMs` (default: 300)

**Returns**: `isDirty`, `isSaving`, `lastSaved`, `saveDraft()`, `setIsDirty()`, `canSave`

**Key Features**:
- Watches all form fields via React Hook Form's `watch()` — sets `isDirty` on any change
- **Duplicate prevention**: Uses a `ref`-based flag (`saveInProgressRef`) to prevent concurrent saves
- **Debouncing**: Prevents saves within `debounceMs` of the last save
- **Retry logic**: Up to 3 retries with exponential backoff (2s, 4s, 8s) on network failure
- **Create vs Update**: If `isEditMode` and `reportId` exist, calls `updateReport`; otherwise `createReport`
- Filters out deed/certificate fields that should only exist in the `deeds` array

### `useJobPolling` — Async Job Status Polling

**File**: `src/hooks/useJobPolling.ts` (198 lines)

Polls the backend for async job completion status (used for background DOCX generation).

**Options**: `onComplete`, `onError`, `autoDownload` (default: true), `maxAttempts` (60), `initialInterval` (2s), `maxInterval` (5s)

**Returns**: `startPolling(jobId)`, `stopPolling()`, `downloadResult()`, `status`, `isPolling`, `error`, `attempts`

**Polling Behavior**:
- Initial poll immediately on `startPolling()`
- Exponential backoff: interval × 1.2 each poll, capped at `maxInterval`

- Transient errors don't stop polling — continues until max attempts
- Max 60 attempts ≈ 2 minutes total

## 13. Form Architecture Patterns

### React Hook Form + Zod Schema Validation

The forms use **React Hook Form** for state management and **Zod** for schema validation:

```typescript
// Schema definition (schemas/validationSchemas.ts)
const schema = z.object({
  applicant_full_name: z.string().min(2, 'Please enter the applicant full name'),
  applicant_id_type: z.string().optional(),
  // ... more fields
});

// In component
const { register, handleSubmit, watch, setValue, formState: { errors } } = useForm({
  resolver: zodResolver(schema),
  defaultValues: { ... }
});
```

### Multi-Step Wizard Pattern

The `MultiStepForm` component implements a wizard pattern:

1. **Step State**: `currentStep` index into `FORM_STEPS` array
2. **Step Navigation**: Forward/backward buttons. Forward validates the current step's fields before advancing.
3. **Per-Step Validation**: Each step has its own Zod schema. Only the current step's fields are validated on "Next".
4. **Draft Saving**: The `useDraftManager` hook watches all form fields and saves to the backend. Draft saves happen:
   - On explicit "Save Draft" button click
   - Before navigating away (via `useNavigationBlocker`)
5. **Final Submission**: Changes `status` from `draft` to `completed` and saves.

### Form Data Transformation

Data flows through three stages:
1. **Frontend Form State**: React Hook Form manages the full form object with all fields
2. **API Request**: Before sending, `filterReportData()` removes fields that exist in structured arrays (deed fields, certificate fields) and strips read-only server fields (id, user_id, created_at, etc.)
3. **Backend Schema**: FastAPI Pydantic models validate and store the data

### Draft Auto-Save

The `useDraftManager` hook provides backend-backed drafts:
- Watches all form fields via React Hook Form's `watch()` subscription
- Sets `isDirty = true` on any change
- `saveDraft()` sends the full form data to `POST /api/reports` (create) or `PUT /api/reports/:id` (update) with `status: 'draft'`
- Deduplication via ref-based flags prevents concurrent save operations
- Debouncing (300ms default) prevents rapid successive saves
- Retry logic (3 attempts, exponential backoff) handles network failures

### Conditional Field Rendering

Many fields are conditionally shown based on other field values:
- Building sections hidden for `bare_land` report type
- Deed fields shown/hidden based on `property_identification_type`
- Organization submission fields shown when `request_type === 'organization_request'`
- Additional owner fields shown when `has_additional_owner === 'Yes'`
- Special note text shown when `has_special_note === 'Yes'`

### Architecture Decisions

**Why React + Vite, not Next.js?**
This is a pure SPA with no SEO requirements. All content is behind authentication. Vite provides faster builds and simpler configuration than Next.js for this use case. No server-side rendering needed.

**Why Tailwind CSS + Material UI (hybrid)?**
Tailwind handles 90% of styling (layout, spacing, colors, responsive design, animations). MUI provides complex pre-built widgets that would take significant effort to recreate (DatePicker with calendar popup, Autocomplete with async loading and filtering, Dialog with focus trapping and accessibility).

**Why Zod over Yup?**
Zod is TypeScript-first — schemas produce TypeScript types automatically (`z.infer<typeof schema>`). Better integration with the TypeScript ecosystem and React Hook Form via `@hookform/resolvers`.

**Why encrypted sessionStorage, not httpOnly cookies?**
The backend uses JWT bearer tokens (not session cookies). Tokens need to be accessible to JavaScript for Axios Authorization headers. sessionStorage (not localStorage) ensures tokens are cleared when the tab closes. AES encryption adds defense-in-depth against XSS reading token values directly. The comments in `secureStorage.ts` acknowledge this is not a complete XSS defense — CSP headers and input sanitization are the primary protections.

**Why React Hook Form over Formik?**
React Hook Form has better performance (uncontrolled components, minimal re-renders) which matters for these large forms with 100+ fields. The `watch()` API enables efficient draft auto-saving.

### Domain Knowledge

**Sri Lankan Land Measurements**: The Acres-Roods-Perches (A-R-P) system is the standard for property transactions in Sri Lanka. 1 Acre = 4 Roods = 160 Perches. The `extentCalculator.ts` utility handles all conversions.

**Administrative Divisions**: Sri Lanka's hierarchy is Province → District → Divisional Secretariat (DS Division) → Grama Niladari (GN Division). The `useAdministrativeDivisions` hook fetches this hierarchy from the backend.

**NIC Validation**: Sri Lankan National Identity Cards come in two formats — old (9 digits + V/X, where females add 500 to day-of-year) and new (12 digits with 4-digit year).

**Professional Credentials**: Valuers in Sri Lanka have specific credential patterns — membership levels (Fellow, Associate, etc.), designated professional bodies, panel valuer status with specific banks.

**Valuation Reports**: Professional property valuation reports follow a standardized format expected by Sri Lankan banks and legal institutions. The DOCX generator on the backend produces these formatted reports.

### Component Patterns — How to Add New Features

**Adding a New Form Step** (to property report):
1. Create a new step component in `src/components/` (follow `ApplicantAndPurposeStep.tsx` pattern)
2. Add the step to `FORM_STEPS` in `constants/multiStepFormConstants.ts`
3. Add Zod schema for the step's fields in `schemas/multiStepFormSchemas.ts`
4. Add the step rendering in `MultiStepForm.tsx`'s `renderStep()` function
5. Add types to `types/index.ts` if needed

**Adding a New Report Type**:
1. Create a new page component in `src/pages/`
2. Add routes in `App.tsx` (wrapped with `ProtectedRoute`)
3. Add the type to `ReportTypeSelection.tsx`
4. Update `ReportEditRouter.tsx` to handle the new type
5. Add API methods to `api.ts` if the backend has new endpoints
6. Add types to `types/index.ts`

**Adding a New API Endpoint**:
1. Add the method to the appropriate namespace in `services/api.ts`
2. Add request/response types to `types/index.ts`
3. The CSRF interceptor and retry logic apply automatically

**Adding a New Utility**:
1. Create the file in `src/utils/`
2. Export functions (avoid classes unless state is needed)
3. Add types inline or in `types/` if shared
